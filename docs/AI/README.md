# Documentation routing

Read only what the task needs. Paths below are relative to this directory.

For substantial work, always read `project_context.md` and `current_status.md`.
Then select the relevant row; combine rows only for tasks spanning those areas.

| Task | Additional documents |
| --- | --- |
| Architecture/design | `../architecture.md`, `workflow.md`, `coding_principles.md`, `roles/architect.md` |
| Backend | `../architecture.md`, `coding_principles.md`, `roles/backend.md` |
| Frontend | `coding_principles.md`, `roles/frontend.md` |
| Review/testing | `definition_of_done.md`, `roles/qa.md` |

Read `workflow.md` when execution guidance is needed and `definition_of_done.md` before declaring substantial work complete. Small, isolated edits need only directly relevant context.

Do not preload every document or every role. Follow links only when relevant.
Project scope lives in `project_context.md`; boundaries in `../architecture.md`; progress and next task in `current_status.md`. Role files add focused guidance, not separate process or agents.
