# Development workflow

1. Understand the requested outcome, scope, and constraints.
2. Use `README.md` here to read only relevant documentation.
3. Inspect the existing implementation and available checks before editing.
4. Make the smallest reasonable change that meets the task.
5. Run relevant tests and applicable typecheck/lint; use `definition_of_done.md` for completion checks.
6. Review the diff for correctness, scope, and sensitive data.
7. Update `current_status.md` if phase, completion, decisions, limitations, or next task materially changed; update architecture documentation if boundaries changed.

Report the result, checks run, and known limitations. If a required check cannot run, report it explicitly.
